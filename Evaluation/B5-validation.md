## Watch protocol v1

Only immediate WatchConnectivity messages are used. Packets carry nonce, capture session/generation/source, fresh epoch, sequence, event UUID, original created/expiry times, a small cue family and bounded text. Size limit 8192 bytes; cue lifetime at most 300 ms; 128 retained accepted IDs per bounded handshake. No application-context, background transfer, file transfer, retransmission or stored cue backlog.

Watch starts a probe at local `p`; phone replies with its own monotonic `t`; watch receives at `r`. A round trip over 200 ms is rejected. Phone-minus-watch clock offset lies in `[t-r, t-p]`, so the upper bound `t-p` plus a provisional 10 ms margin is used to expire early. A handshake lasts at most two seconds and is refreshed with a new nonce. Raw uptimes are never directly compared as if synchronized. Sequence/cancel, wrong session/generation/epoch/nonce, duplicate IDs, nonfinite/future/out-of-budget/expired packets and reconnects fail closed. Software acceptance is acknowledged; it is not proof of a felt haptic. Phone starts without waiting for any acknowledgement.

The watch supports foreground-only explicitly enabled Research, status, five local text/tap previews, and Pause both. Background disables watch Research until explicitly re-enabled. Pause clears local state first and reports phone pause confirmed only on the matching acknowledgement. Unreachable phone pause remains unconfirmed. Phone session stop invalidates its epoch; reconnect requires a new probe and never drains old cues.

Every watch meaning uses one immediate attention tap plus text. WatchKit supplies no pattern-cancellation API for an already issued system tap. Therefore physical cancellation/latency/comprehension and any stricter no-output-after-pause requirement remain **unaccepted**, even if software expiry and queue cancellation pass. No watch hardware was available in this session; R08 hardware validation is blocked, not passed. See the [protected physical protocol](Accessories/B5-physical-protocol.md).
